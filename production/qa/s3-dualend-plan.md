> 编制：质量负责人 严守真（quality-lead）

## 0. 目标与范围

验证核心闭环在 **PC 横屏（≥1024）** 与 **移动竖屏（<768）** 双端均跑通且**不破版**，覆盖：旋转 / 分辨率切换不崩、焦点不丢、热区命中率 ≥95%（移动 ≥44px）、五行形状冗余灰阶可辨。最终与 `s2-vertical-slice-playtest.md` **场景 E** 截图做比对，回填 `production/qa/` 作为 S3 体验证据。

- **双端跑通**：场景 A–D 闭环在两端各跑一遍（DoD1）。
- **旋转 / 分辨率**：横↔竖、≥1024↔<768 切换不崩、焦点不丢（E5-S4 AC1 / S3-DualEnd AC2）。
- **指标达标**：双端断点 0 溢出 / 0 裁切；热区点击命中率 ≥95%（移动 ≥44px）；五行形状冗余灰阶可辨（S3-DualEnd AC3）。

## 1. 双端测试矩阵（Test Matrix）

| 端 | 分辨率 / 方向 | 跑通场景 | 断点 / layout_mode | 重点观察 |
|---|---|---|---|---|
| **PC 横屏** | 1280×720 / 1440×900 | A–D 闭环 | ≥1024 → `multi` 多栏 | 多栏不破版、无横向滚动条、HUD 完整 |

| 维度 | 判据 | 来源 | Pass / Fail |
|---|---|---|---|
| **D1 断点不破版** | 双端 0 溢出 / 0 裁切（关键容器 `size` 不超出视口、无横向滚动条） | S3-DualEnd AC3 / Standard | 严重破版致无法操作 → FAIL |
| **D2 旋转不崩** | 横↔竖 / ≥1024↔<768 切换无崩溃 / 异常，布局随断点重排 | E5-S4 AC1 / Standard I | 切换崩溃 → FAIL |
| **D3 焦点不丢** | 旋转 / resize 后当前聚焦 Control `has_focus()` 仍 true，或合理回退到同语义节点（如「编队确认」始终可聚焦） | E5-S4 AC2 / Comprehensive L | 焦点跳到无关节点 / 丢失 → ⚠️ CONCERNS→FAIL |

## 3. 执行步骤（Executable Steps）

### 3.1 PC 横屏（≥1024）
1. Godot 编辑器 / 导出包，视口设为 **1280×720**（或 1440×900）。
2. 跑场景 A–D：主菜单 → 抽卡 → 图鉴 → 养成 → 编队 → 推图首关 / Boss → 结算。
3. 检查 **D1**：多栏布局关键容器（顶栏货币 / 编队栏 / 战斗 HUD）不溢出、无横向滚动条；技能按钮热区 ≥44×44 可点。
4. 检查 **D5**：五行形状冗余（圆/三角/方/菱/五边）在默认色板下可辨。
5. **截图**各屏（主菜单 / 抽卡 / 编队 / 战斗 HUD / 结算）留存比对。

### 3.2 移动竖屏（<768）
1. 真机 / 模拟器，视口 **390×844**（或 360×800），竖屏。
2. 同跑场景 A–D；检查 **D1**：单列 / 仅留关键数值，不拥挤、无横向滚动条。
3. 检查 **D4**：技能 / 操作按钮 `size` ≥ (44,44)；连续点击 20 次统计误触（命中率 ≥95%）。
4. 检查 **D5**：五行形状冗余在**灰阶**下仍可区分（色盲友好）。
5. **截图**各屏（含灰阶版）留存比对。

### 3.3 旋转 / 分辨率切换（E5-S4 AC1 / S3-DualEnd AC2）
1. PC：横屏 1280×720 ↔ 窗口缩放 1440×900，聚焦某节点（如选中式神卡）→ 切换后断言 `has_focus()` 仍 true（**D3**）。
2. 移动：竖屏 390×844 ↔ 横屏 844×390（模拟旋转），聚焦节点焦点不跳无关节点（**D2 / D3**）。
3. ≥1024 ↔ <768 断点切换：`UIThemeController.layout_mode` 正确切换，焦点合理回退到同语义节点（如「编队确认」始终可聚焦）。
4. 记录旋转 / resize 事件触发后的焦点链日志（无异常、无崩溃）。

### 3.4 热区命中率统计（D4）
- 在移动端对核心可交互控件（抽卡 / 编队槽 / 技能按钮 / 结算操作）各连续点击 **20 次**，记录误触（点偏 / 未命中目标）次数。
- 公式：`命中率 = (总点击 − 误触) / 总点击 × 100%`；要求 **≥ 95%**（即 20 次中误触 ≤1）。

### 3.5 灰阶可辨核对（D5）
- 对五行形状渲染节点应用去色（`modulate` 置灰 / 截图转灰阶），核对 5 形状轮廓互异、无歧义；不依赖色相即可辨别。
- 附灰阶截图比对（与 `s2-vertical-slice-playtest.md` 场景 E 观察点一致）。

## 5. Pass / Fail 判定

| 情形 | 判定 | 处置 |
|---|---|---|
| 双端跑通 + D1–D5 全达标 + 截图比对一致 | **PASS** | 关闭 S3-DualEnd（DoD1/12/19） |
| 轻微裁切 / 热区临界 / 灰阶略弱（D5） | ⚠️ CONCERNS | 限期优化，登记 Bug，不阻断放行 |
| 热区命中率 <95% 或热区 <44px 致不可点 | **FAIL** | 开 Bug 回 eng（Standard J） |
| 旋转 / 分辨率切换崩溃，或焦点跳无关节点 / 丢失 | **FAIL** | 开 Bug 回 eng（E5-S4） |
| 双端严重破版致无法操作 | **FAIL** | 开 Bug 回 eng，重验 |

> 本计划为**环境阻塞项**：沙箱内无 Godot / 真机，不在此执行。结果待 PAT 到位、推送后在真机回填（见 `s3-final-qa-gate.md` §3 #3）。

## 6. 真机 / 模拟器设备建议

| 端 | 推荐设备 | 分辨率 | 用途 |
|---|---|---|---|
| **PC** | 桌面浏览器 / 编辑器 + 导出包 | 1280×720、1440×900 | 横屏多栏验证 |
| **移动（真机优先）** | Android 中端机（如 骁龙 6xx+ / 4GB+） | 390×844、360×800 | 竖屏单列 + 热区 + 灰阶 |
| **移动（模拟器）** | Android Emulator（Pixel 系列） | 390×844 | 无真机时的替代 |
| **iOS（可选）** | iPhone SE / 中端 | 390×844 | 竖屏 + Basic 观感 |

> 旋转验证建议**真机优先**（模拟器旋转与真机传感器有差异）；焦点链日志用 Godot `get_viewport().gui_get_focus_owner()` 记录。
