# 仙侠卡牌项目 · UX 规格（Phase 4 预制作 · MVP 核心循环）

> 范围：仅 MVP 核心循环屏幕（主菜单 → 抽卡 → 图鉴 → 养成 → 编队 → 推图战斗 → 结算 → 资源回流），不铺全系统。
> 对齐基线：01-concept.md（P1–P3 / R1–R5 / 范围分层）、02a-gdd-mvp.md（B1–B5）、02b-gdd-full.md（A1–A5 / 依赖总图）、art/art-bible.md（§3/§5/§7/§8）、art/accessibility-spec.md（Basic/Standard/Comprehensive 三级）、docs/architecture/01-architecture.md（§1.5 响应式 UI / §1.7 存档 schema / §1.8 事件总线 / §四 控制清单）。
> 引擎/平台：Godot 4.x 2D-first；PC 横屏(≥1024) + 移动竖屏(<768)，断点口径对齐 art-bible §7 / accessibility-spec §3。
> 评审：solo / lean；文档聚焦方向与规范。
> 编写：design-strategist（文策渊）。

## 0. 范围与基线约定

- **可访问性落地口径**（对齐 accessibility-spec §0）：MVP 强制 **Basic 全项 + Standard 主体**（Standard 中「色盲模拟测试/CVD 滤镜」先以工程 dev 工具 + 美术审查落地，玩家端 CVD 滤镜可作为 Standard 尾声项）；**Comprehensive** 作为核心层与长线分阶段目标，本规格仅标注接口预留，不铺实现。
- **双端断点**（art-bible §7 / A5 / accessibility §3）：`≥1024` 横屏多栏（左列表/中战场/右信息）；`768–1024` 混合自适应（折叠次要栏）；`<768` 竖屏单列堆叠 + 底部 Tab（关键操作拇指可达）。
- **每屏一套 UI 描述**（架构 §1.5 ADR-001）：同一 Control 子树经 `UIThemeController` 按 `layout_mode` 切换布局变体，不另出独立场景（R3 缓解）。
- **输入抽象**（架构 §1.5 / ADR-003 `InputBridge`）：统一抽象意图 `ui_select / ui_back / drag / long_press / hover_peek`，详见 §3。
- **事件驱动反馈**（架构 §1.8 事件总线）：顶栏货币用 `economy:currency_changed`；出货用 `gacha:shikigami_obtained`；养成用 `cultivate:level_up/breakthrough/awakened`；战斗用 `battle:*`；UX 反馈层只 listen 事件，不直接 import 管理器 → 无环。
- **设置落点**（架构 §1.7 schema / accessibility §5 CONCERN 桥接项）：高对比、文本缩放、减少动效、CVD、动态文本等开关统一由 `AccessibilitySettings` 单例（或并入 `UIThemeController` 的 peer autoload）持有，`accessibility_changed` 信号驱动主题/shader。本规格引用该单例为设置真源，待 Phase 4 落实桥接（见 §6 待对齐项）。

## 1. 屏幕流（Screen Flow）

核心循环 8 节点；方括号【】为屏幕，圆括号( ) 为弹窗/overlay，实线 → 为主路径跳转，虚线 ╌ 为事件/数据回流。

```
[启动/加载] ──读档(schema v1)──► 【主菜单 MainMenu】
                                              │
        ┌──────────────┬──────────────┬──────┴──────┬──────────────┐
        ▼              ▼              ▼              ▼              ▼
  【抽卡 Summon】 【图鉴 Codex】 【养成 Cultivate】 【编队 DeckBuild】 【推图战斗 Battle】
        │              │              │              │              │
   (羁绊序章弹窗)     │         (突破飞升特效)    │         关卡选择→战斗HUD
        │              │              │              │              │
        └─图鉴点亮────►│◄─(可选)跳转─┤◄─(可选)跳转─┤              │
                       │              │              │              │
                       └──────┴──────┴──────────────┘              │
                                                                    ▼
                                                          胜利/失败 ► 【结算 Settlement】
                                                                          │
                                                                          ▼
                                                          (资源回流 overlay：顶栏飘字+领取)
                                                                          │
                                                                          ╎ 写回经济(B1)
                                                                          ╎ 顶栏货币 +N（tabular）
                                                                          ▼
                                                              闭环回到 ► 【抽卡 Summon】(用回流符箓)
                                                                  └─或 回【主菜单】/【图鉴】/【养成】
```

**跳转规则要点**
- 主菜单为唯一枢纽；任一核心屏 `ui_back` 均回主菜单（战斗内"放弃"亦回主菜单，不丢进度）。
- 抽卡出货后**不强制回主菜单**：提供「去养成 / 去编队 / 看序章」快捷入口（减少回枢纽跳数，见 §4 卡点 #3）。
- 养成/编队互达：养成页选中式神可「一键编队」带入空槽；编队页选中槽位可「去养成」跳对应式神。
- 资源回流不是独立全屏，是结算页内的奖励领取 overlay + 顶栏货币实时更新；领取后给「用回流符箓去抽卡」CTA，闭合循环。

## 2. 逐屏交互规格（MVP 范围）

通用约定（每屏继承）：
- 顶栏/常驻货币：`fu_lu`(符箓)/`ling_yu`(灵玉)/`ling_qi`(灵气)/`po_dan`(突破丹)/`jue_xing_shi`(觉醒石)，数值一律 **tabular nums**（art-bible §3 / accessibility C），PC 置角落、移动常顶栏（B1 双端要点）。
- 所有反馈满足 **Basic A 对比度**（正文≥4.5:1、大标题≥3:1）、**Basic B 高对比模式**、**Basic C 文本缩放 100–130% 不破版**、**Basic E 色盲冗余**（稀有度=颜色+边框纹理+角星 1/2/3；五行=图标+形状 圆/三角/方）。
- Standard 主体项（J 触控≥44px / K 字体层级 / I 减少动效 / H 动态文本 / G CVD）按屏相关项落地，下表逐屏标注。

### 2.1 主菜单（MainMenu）
- **屏幕目的**：核心循环入口枢纽，提供通往各功能屏 + 设置（可访问性开关入口）。
- **关键元素**：① 顶栏货币状态（常驻，tabular）；② 主功能入口宫格/列表（抽卡/图鉴/养成/编队/推图）；③ 设置入口（高对比/缩放/减少动效/CVD 开关）；④ 氛围背景（art-bible 锚点1 御剑长空 / 锚点2 悬浮宗门仙山，降饱和+暗角不抢前景）。
- **主操作**：`ui_select` 进入各功能；`ui_back` 无（已是最外层，PC 对应 Esc 退出/系统）。
- **信息层级**：L1 货币栏（常驻）＞ L2 主功能入口（主视觉权重）＞ L3 设置/帮助。
- **双端布局**：
  - PC(≥1024)：左/上主功能导航 + 右/中氛围大图；货币置右上角；hover_peek 预览功能说明（描边加厚+图标态变化，不靠纯发光，accessibility §3.1）。
  - 移动(<768)：单列堆叠 + **底部 Tab**（抽卡/图鉴/养成/编队/推图，各 ≥44×44px，thumb 可达）；货币常顶栏；无 hover → 入口图标用「形状+文字」双编码。
- **可访问性映射**：Basic A/B/C/E 全满足。Standard 主体：**J**（底部 Tab 热区强制）/ **K**（H1 书法标题仅装饰、正文黑体）/ **I**（氛围粒子/视差可关，保留静态背景）/ **H**（入口标签 OS 字体同步）。

### 2.2 抽卡（Summon）
- **屏幕目的**：内容入口；兑现「抽养一体」——出货即羁绊序章叙事钩子（P1）；提供可预期出货节奏与保底。
- **关键元素**：① 卡池选择（常驻 / 新手[前20抽半价、必出 SR]）；② 单抽/十连按钮（主 CTA，显示符箓消耗）；③ 保底进度条（50 软/90 硬，不跨池）；④ 概率公示入口；⑤ 出货演出（卡牌翻面/灵光升腾，SSR 用锚点4 紫宸虹光）；⑥ 羁绊序章弹窗(1–2 屏)；⑦ 货币(符箓)消耗显示。
- **主操作**：`ui_select` 选池/抽卡；`hover_peek`(PC) 或 `long_press`(移动) 看概率/详情；`ui_back` 返回。
- **信息层级**：L1 卡池 + 抽卡主 CTA ＞ L2 保底进度 + 概率入口 ＞ L3 出货演出/序章。
- **双端布局**：
  - PC(≥1024)：多卡并排预览 + 十连动画横向展开；保底进度条完整；hover 看概率/式神详情（描边+图标态）。
  - 移动(<768)：单卡纵向流 + 十连折叠为**结果列表**；保底条收为图标；长按看概率；十连按钮大热区。
- **可访问性映射**：Basic A/B/C（概率/保底数字 tabular）/ **E**（出货稀有度=颜色+边框纹理+角星 1/2/3 三重，art-bible §5/§8）。Standard 主体：**J**（抽卡/十连按钮 ≥44×44）/ **K** / **I**（抽卡长演出可关，保留稀有度边框/角星/数字静态等效）/ **G**（概率公示 + 色盲模拟，三重冗余之上加 CVD 保障）/ **H**。

### 2.3 图鉴（Codex）
- **屏幕目的**：收集展示；抽养一体叙事回看（羁绊序章/短叙事）；已拥有式神浏览与跳转养成/编队。
- **关键元素**：① 式神网格（卡框，引用 **art-bible §5**）；② 稀有度/元素过滤；③ 详情面板（立绘/属性/短叙事/羁绊序章回看）；④ 收集进度。
- **主操作**：`ui_select` 选中式神看详情；可跳转养成/编队；`ui_back` 返回。
- **信息层级**：L1 网格列表 ＞ L2 过滤 + 进度 ＞ L3 详情面板（立绘 60–65% + 叙事文本）。
- **双端布局**：
  - PC(≥1024)：双栏（左网格 + 右详情完整态：flavor text/技能描述，art-bible §5 完整态）。
  - 移动(<768)：单列网格 + 点击展开**底部 sheet 详情**；卡框用**紧凑态**（立绘≥50%、关键数值≥18sp，art-bible §5 移动小屏口径）。
- **可访问性映射**：Basic A/B/C（属性/进度 tabular）/ **E**（网格卡框稀有度三重冗余，引用 art-bible §5 角星/边框）。Standard 主体：**J**（网格卡与 sheet 手柄 ≥44px）/ **K** / **H**（长叙事文本容器自适应、溢出省略+展开，正文≥16sp 对齐 art-bible §3）/ **I**。

### 2.4 养成（Cultivate）
- **屏幕目的**：从「抽到」养成「变强/飞升」，兑现 P2 御剑修真成长爽感；产出可供构筑/战斗读取的最终属性/技能/五行/羁绊标签。
- **关键元素**：① 式神列表；② 详情面板（属性 HP/ATK、战力值、技能/被动槽、五行+羁绊标签）；③ 养成动作按钮（升级[灵气]/突破 1→6 阶[丹+碎片]/觉醒[改写机制]，分支剑修/体修）；④ 突破「飞升」特效、觉醒技演示；⑤ 资源消耗显示。
- **主操作**：`ui_select` 选式神/选养成动作；PC `drag` 批量升级/拖拽分配；移动「一键养成」大按钮（降门槛）。
- **信息层级**：L1 式神列表 ＞ L2 属性面板（战力/属性 tabular）＞ L3 养成动作（升级/突破/觉醒）。
- **双端布局**：
  - PC(≥1024)：双栏（左列表 / 右详情面板），拖拽分配/批量升级。
  - 移动(<768)：底部 Tab 切换（式神/养成/详情），属性面板折叠可展开；「一键养成」主按钮大热区。
- **可访问性映射**：Basic A/B/C（属性/战力 tabular）/ **D**（解锁提示=图标+数字+颜色三重：红剑/蓝盾/绿十字，art-bible §8 不依赖纯色）/ **E**（式神卡稀有度三重冗余）。Standard 主体：**J**（一键养成/动作按钮 ≥44px）/ **K** / **I**（飞升特效/光扫可关，保留属性数字+边框静态等效）。

### 2.5 编队（DeckBuild）
- **屏幕目的**：按五行+羁绊自由构筑（4 式神 + 1 法宝位），兑现 P3 构筑随心；连携预览奖励成队养成。
- **关键元素**：① 卡组槽（4 式神 + 1 法宝位）；② 式神池（已拥有，卡框引用 art-bible §5）；③ 连携预览（羁绊组加成）；④ 五行构成指示；⑤ 确认出战。
- **主操作**：`drag`（PC 拖拽式神入槽；移动拖拽/点选入槽）；`ui_select` 确认；`ui_back` 返回。
- **信息层级**：L1 卡组槽(4+1) ＞ L2 式神池 ＞ L3 连携预览 + 五行构成。
- **双端布局**：
  - PC(≥1024)：多栏（左式神池 / 中战场预览 / 右卡组与连携信息），拖拽编队。
  - 移动(<768)：网格编队（上方卡组槽 + 下方式神网格），点选/拖拽入槽。
- **可访问性映射**：Basic A/B/C（连携数值 tabular）/ **E**（五行=图标+形状 圆/三角/方 冗余，不靠色；稀有度三重冗余）。Standard 主体：**J**（槽位/卡 ≥44px）/ **K** / **I** / **H**。

### 2.6 推图战斗（Battle）
- **屏幕目的**：用养成结果在 1v1 PvE 推图验证策略（前 3 章每章 8–10 关 + 1 Boss）；五行网状克制 + 连携压制主导策略（R5）；叙事与难度曲线。
- **关键元素**：① 关卡选择（章节地图）；② 战斗 HUD——我方 4 式神 + 法宝、敌方单位、行动条/能量、手牌/技能按钮、五行标识、克制标识「克制！」浮字、连携触发横幅（锚点5 五行符文阵意象）；③ 结算入口。
- **主操作**：`ui_select` 选技出招；移动 `drag`/滑动出招；PC 右键快捷；`ui_back`（放弃回主菜单）。
- **信息层级**：L1 战场（双方单位 + 血条/行动条）＞ L2 手牌/技能按钮 ＞ L3 状态（克制标识/连携/回合）。
- **双端布局**：
  - PC(≥1024)：多栏（左式神列表 / 中战场大视野 / 右卡组与信息），右key 快捷。
  - 移动(<768)：**竖向手牌 + 极简 HUD**（只留关键数值）；五行用「图标 + 形状(圆/三角/方)」冗余（art-bible §8）；技能按钮大热区。
- **可访问性映射**：Basic A/B/C（伤害/属性 tabular）/ **D**（战斗反馈**强制三重**：伤害=红剑+「−N」+朱砂；治疗=绿十字+「+N」+青碧；格挡=蓝盾+「−N 挡」+青碧；任何单通道失效仍可读）/ **E**（五行形状冗余 + 稀有度冗余）。Standard 主体：**J**（技能按钮 ≥44×44）/ **K** / **I**（克制特效/视差/Boss 3D 演出可关，保留浮字/横幅静态等效）/ **G**（CVD 滤镜对五行配色做色相安全重映射）。

### 2.7 结算（Settlement）
- **屏幕目的**：战利品展示（符箓/丹/石），章节星级 + 首通奖励（回流 B1 起点）；提供再战/回主菜单/去抽卡。
- **关键元素**：① 胜负结果；② 奖励列表（符箓/突破丹/觉醒石，tabular）；③ 星级 + 首通奖励弹窗；④ 后续操作（再战 / 回主菜单 / 用回流符箓去抽卡）。
- **主操作**：`ui_select` 领取/再战/返回；`ui_back` 返回。
- **信息层级**：L1 胜负 + 奖励（主）＞ L2 星级/首通 ＞ L3 后续操作。
- **双端布局**：
  - PC(≥1024)：多栏结算面板（结果 + 奖励明细 + 操作）。
  - 移动(<768)：单列结算页（奖励卡列表纵向，数值≥18sp）。
- **可访问性映射**：Basic A/B/C（奖励数字 tabular）/ **D**（若有伤害总结沿用红剑/绿十字三重）/ **E**（奖励卡稀有度冗余）。Standard 主体：**J**（操作按钮 ≥44px）/ **K** / **I** / **H**。

### 2.8 资源回流（ResourceReturn · overlay/flow，非独立全屏）
- **屏幕目的**：将战斗产出（符箓/丹/石）写回经济闭环（B1 回流源），驱动回到抽卡，闭合「抽→养→筑→战→回流」飞轮。
- **关键元素**：① 顶栏货币实时更新（+N 飘字，青碧 #4FA39B 灵力色，art-bible 反馈）；② 奖励领取（邮箱/玉质感弹窗，锚点4 鎏金 #CBA75C 描边）；③ 闭环提示 + 「去抽卡」CTA。
- **主操作**：自动/一键领取 → 顶栏更新 → `ui_select` 去抽卡。
- **信息层级**：顶栏常驻货币（实时）＋ 领取弹窗（主反馈）。
- **双端布局**：
  - PC(≥1024)：货币置角落 + 飘字；结算弹窗居中。
  - 移动(<768)：货币常顶栏 + 飘字；领取弹窗底部 sheet。
- **可访问性映射**：Basic A/B/C（货币 tabular nums 防跳）/ **D**（获得飘字=青碧+图标+数字 三重，不靠纯色）/ **E**。Standard 主体：**J**（领取/CTA ≥44px）/ **K** / **I**（飘字粒子可关）。

## 3. 导航与输入范式（统一，对齐 ADR-003 `InputBridge`）

抽象意图集（架构 §1.5 / 控制清单）：`ui_select / ui_back / drag / long_press / hover_peek`。PC 键鼠与移动触控统一映射到这些意图，业务屏只认意图、不认硬件。

| 抽象意图 | PC 键鼠映射 | 移动触控映射 | 降级/等价 | 主要使用屏 |
|---|---|---|---|---|
| `ui_select` | 左键点击 / Enter / 空格 | Tap | 焦点环(Comprehensive L) | 全屏 |
| `ui_back` | Esc / 左上返回 / 浏览器后退 | 系统返回手势 / 左上返回 / 底部 Tab | — | 全屏 |
| `drag` | 鼠标拖拽（式神入槽、资源分配、滑动出招可选） | 拖拽（编队入槽）/ 滑动（出招） | — | 编队、战斗、养成(PC批量) |
| `long_press` | 右键长按（等效 context，非主路径） | 长按（看概率/详情/连携预览） | 移动无 hover → 长按/点击展开替代 | 抽卡、图鉴、编队、战斗 |
| `hover_peek` | 悬停窥视（看概率/式神详情/关系网/技能预览，描边加厚+图标态变化，不靠纯发光） | **无悬停** → 由 `long_press`/点击展开承接 | 移动端截断为 long_press | 抽卡、图鉴、养成、编队 |

**统一导航规则**
- 主菜单为根；所有核心屏 `ui_back` 收敛回主菜单；战斗"放弃"亦回主菜单且不丢进度（读 `GameState`，schema v1）。
- 焦点顺序：逻辑 tab 顺序 = 视觉阅读顺序（PC 高可见焦点环；Comprehensive L 手柄/键盘全遍历，装饰节点显式排除）。
- 底部 Tab（移动）为全局常驻导航，thumb 可达，热区 ≥44×44（Standard J）。
- 所有意图经 `InputBridge` 归一后转发；屏幕不直连硬件事件 → 与 EventBus 解耦一致。

## 4. 核心循环可读性检查（抽 → 养 → 筑 → 战 → 回流）

走查「抽→养→筑→战→回流」在 UX 上是否顺畅，标注潜在卡点：

- **抽（Summon）**：入口清晰，新手池半价+必出 SR 降首抽挫败（R1 缓解），出货即羁绊序章（P1 抽养一体钩子）。
  - 卡点 #1：**符箓枯竭断点**——符箓不足时玩家若无引导会"卡死"。缓解：符箓不足时抽卡按钮下方显「去推图产出符箓」CTA（指向战斗屏），并提示每日免费十连独立额度（10 符箓/日，pass2 修正解耦）。
- **养（Cultivate）**：PC 双栏清晰，移动「一键养成」降门槛；突破飞升特效给 P2 爽感。
  - 卡点 #2：**养成资源瓶颈**（灵气/丹/石不足）→ 卡养成。缓解：资源不足时养成动作按钮置灰并显「产出源：推图/Boss/日常」引导；丹/石周产有限，UI 明示周预算剩余（tabular）。
- **筑（DeckBuild）**：拖拽/点选编队 + 连携预览，兑现 P3 表达。
  - 卡点 #3：**新手不懂五行克制** → 编队盲目。缓解：前 3 章敌人刻意铺不同五行做教学（B4），编队页常驻「五行构成 + 克制提示」；连携预览用醒目横幅+形状冗余，避免纯色。
- **战（Battle）**：回合制选技，克制/连携浮字反馈强。
  - 卡点 #4：**移动端 HUD 密度**——<768 屏易挤。缓解：移动 HUD 极简（只留关键数值），五行靠「图标+形状」冗余保证克制信息不丢；单场时长上限 2–4min（B4 数值）防冗长。
- **回流（ResourceReturn）**：结算→奖励→顶栏更新→去抽卡，闭环闭合。
  - 卡点 #5：**回流与抽卡之间缺乏"爽点连接"**。缓解：结算页直接给「用回流符箓去抽卡」CTA，顶栏 +N 飘字（青碧+图标+数字三重）即时兑现回流，缩短"变强→再抽"的心理距离。

**全局可读性风险（最高优先）**：卡点 #1/#2 是核心循环断流的主因——任何消耗点（抽卡/养成）在资源不足时若无"产出源引导"会直接卡死留存飞轮。UX 层统一规则：**所有资源消耗点，资源不足时必显"去哪产出"引导入口**，而非仅置灰。此为 MVP 验收关键项。

## 6. 待主理人知悉 / 待对齐项（Handoff Notes）

1. **CONCERN 桥接（架构缺口）**：accessibility-spec §5 建议独立 `AccessibilitySettings` 单例 + `accessibility_changed` 信号 + CVD 滤镜 + `MotionScale` 动效总线，当前架构已部分吸收进 `UIThemeController` 但未显式预留。本 UX 规格以该单例为设置真源，**建议 Phase 4 落实桥接**（架构控制清单末项已标记）。
2. **资源断流引导（验收关键）**：§4 卡点 #1/#2 要求"所有资源消耗点资源不足时显产出源引导"，需 engineering-lead 在 `EconomyManager` 暴露"资源缺口→推荐产出源"查询接口，UX 层接 `economy:currency_changed` 渲染引导。
3. **每日免费十连独立额度**（Phase 4 定稿 · R4）：pass2 修正（10 符箓/日，不计入软预算）定稿方向——① 顶栏拆两格：左格「玩法产出符箓（fu_lu 实时）」＋ 右格独立徽标「免费十连额度 10/日」，视觉独立计数避免与玩法产出混淆；② 抽卡屏十连按钮下方一句话「每日免费十连额度 10 符箓，独立于玩法产出，不计入软预算」。解耦逻辑已在 S1 落地（economy_config.free_ten_pull=10），本项仅补 UI 文案层，不触碰经济逻辑。
4. **移动端 HUD 极简验证**：战斗 <768 的 HUD 密度与五行形状冗余清晰度，需在首屏 smoke 用真机验证（关联架构 CI smoke + Standard J lint）。
5. **减少动效静态等效**：所有动效（抽卡长演出/飞升/克制特效/飘字）在 `reduce_motion` 开启时须保留边框/角星/数字/图标的静态等效（accessibility I），列为 MVP 验收项。
